1. RUNBOOK (how to run / continue this project)
--------------------------------------------------------------------------------
- Start MySQL first: XAMPP Control Panel -> MySQL Start.
  (If the app reports "Database Offline", the server is down — restart it.
  The mysqld process has died on its own several times; this is
  environmental, never app code.)
- Fresh database install: phpMyAdmin -> Import ONE file only:
    Database/school_canteen_db.sql        (canonical, final schema + seed)
  Do NOT import anything else. Phase0_Patch.sql is ONLY for upgrading a
  database created before the merge (it is idempotent / safe to re-run).
- Run:  CANTEENSYSTEM/bin/Debug/CANTEENSYSTEM.exe
  (Always Rebuild in Visual Studio / MSBuild before running after any
  code change — a stale binary masks fixes. Check the exe timestamp.)
- Entry: frmSystemSelect (front door)
    KIOSK button -> frmKiosk (no login) | STAFF button -> frmLogin
- Logins (seed data):
    Admin tab   : admin    / admin123   -> Dashboard
    Cashier tab : cashier1 / 1234       -> POS   (staff1 / 1234 also works)
    Employee (salary PIN dialog): john.doe / PIN 1234
- MySQL: Server=localhost, Database=school_canteen_db, Uid=root, Pwd=(blank).
  Single connection string lives in App.config <connectionStrings
  name="CanteenDb">, read by DbHelper. 5s connection timeout (fail fast).
- Kiosk flow: Kiosk order -> Pending -> POS opens it via F6 (or the
  PENDING button) -> counter payment completes it atomically.
- Git: repo has full history. The deleted original dump
  (school_canteen_db(1).sql) is recoverable via `git show HEAD:...`.

--------------------------------------------------------------------------------
2. DATABASE MAP
--------------------------------------------------------------------------------
Database: school_canteen_db (MariaDB 10.4, utf8mb4_general_ci).
Tables (11): users, employees, categories, products, transactions,
transaction_details, kiosk_orders, kiosk_order_details, salary_deductions,
stock_movements, audit_logs.

Columns ADDED after the base dump (all in the merged file + live DB):
- transactions : transaction_number (TRN-YYYYMMDD-####), payment_method,
  status (Completed), employee_number (NULL), kiosk_order_id (NULL)
- kiosk_orders : order_type (DineIn), payment_method (Cash),
  employee_number (NULL, kiosk salary linkage)
- employees    : sd_remaining (running balance, see section 4)

Engine guards (live + both SQL files):
- trg_employees_bi / trg_employees_bu : normalize
  employees.deduction_status to UPPER on write; reject anything outside
  PENDING/COMPLETE (ERROR 1644). NOTE: a plain CHECK constraint was tried
  first and is USELESS here — the column collation is case-insensitive,
  so 'Pending' passed the CHECK. Triggers are the correct mechanism.

Business rules enforced:
- Salary deductions: NO LIMIT (spec). salary_deductions rows accumulate;
  deduction_status enum is Pending/Deducted/Cancelled (leave this casing).
- Low stock := 0 < stock_quantity <= 10  (uniform: all reorder_level = 10).
  Out of stock := stock_quantity = 0.
- employees.deduction_status is ALWAYS ALL-CAPS (PENDING/COMPLETE).

5. CONVENTIONS (follow these going forward)
--------------------------------------------------------------------------------
- ZERO Designer-file edits by the assistant; all UI additions are runtime
  code (user works in VS concurrently — never clobber their saves).
- DbHelper / Session / Navigator / AuditLog are single sources; no new
  connection strings or session objects.
- row.Tag carries product_id in carts; never match stock by product_name.
- Salary writes go through SalaryService; sales through
  TransactionService.Checkout (always pass kioskOrderId through).
- Rebuild before every run; verify via tasklist /v (Get-Process titles
  can be stale); kill stale instances before rebuilding (file lock).
- Headless tests can't observe Visible/scroll/dialogs; use off-screen STA
  windows (-5000,-5000) with DoEvents pumps for real layout/scroll proof,
  and read state BY SCREEN POSITION where designer names lie (the
  swapped alert labels lesson).

7. KNOWN QUIRKS / LESSONS
--------------------------------------------------------------------------------
- mysqld dies on its own: restart via XAMPP; app shows offline error.
- Stale binaries mask fixes: always rebuild; check exe timestamp.
- Headless Visible=False poisons Visible/scroll/position reads; use
  off-screen shown windows for layout proof.
- Collation beats CHECK constraints (use triggers for case rules).
- WinForms scrollbar/wheel need REAL overflow; auto-fit layouts and
  dock overlaps silently disable scrolling (pending grid saga).
- FirstDisplayedScrollingRowIndex silently ignores sets without a
  current cell; CurrentCell anchoring always works (moves selection).
- Native WM_VSCROLL to DataGridView proven no-op; don't use it.
